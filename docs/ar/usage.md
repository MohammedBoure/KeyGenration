# استخدام Activateur RMS

`ActivateurRMS.exe` واجهة Windows مكتوبة بـ Rust لإنشاء مفاتيح التفعيل.
تجهز الواجهة خدمة التوليد المحلية تلقائيا عند الحاجة، ولا تعرض إعدادات
الخادم للمستخدم. لا تتصل الواجهة أو الخدمة بقاعدة PostgreSQL مباشرة؛
الاتصال بقاعدة البيانات يتم عبر Cloud API فقط.

## البرامج المدعومة

| البرنامج المعروض | القيمة المرسلة | مثال مفتاح لنفس كود الطلب |
| --- | --- | --- |
| تسيير المطاعم | `Restaurant` | `EE8C-551F-0A90-73F5` |
| تسيير مخزون المخابر | `Lab` | `F74D-9047-9117-B8AF` |
| تسيير محلات الذهب | `Jewelry` | `EF4E-047E-2AF5-63B7` |

الأمثلة تستخدم `Request Code` بقيمة `F81A-67A7-C6AA`. خوارزمية
`Restaurant` متوافقة مع النسخة السابقة.

## محتويات حزمة Windows

تنتج أداة التغليف الحزمة التالية:

```text
dist\windows\ActivateurRMS\
|-- ActivateurRMS.exe
|-- SHA256SUMS.txt
|-- KeyGenService\
|   `-- KeyGenService.exe
`-- nssm\
    `-- nssm.exe
```

قبل بناء الحزمة، انسخ قالب إعداد العميل داخل مجلد التغليف:

```powershell
Copy-Item .\packaging\windows\client.env.example .\packaging\windows\.env
```

حرر `packaging\windows\.env` واضبط القيم:

```dotenv
KEYGEN_CLOUD_API_URL=https://activation.example.com
KEYGEN_API_SECRET_TOKEN=replace-with-api-token
KEYGEN_LISTEN_ADDRESS=127.0.0.1:45632
KEYGEN_STATUS_INTERVAL_SECONDS=300
KEYGEN_UPLOAD_INTERVAL_SECONDS=5
```

يقرأ البناء هذه القيم ويضمّن القيم المصفاة فقط في ملفي Rust التنفيذيين؛
لذلك لا تعرض حزمة المستخدم ملف إعداد ولا تظهر القيم في واجهة البرنامج.
لا تضع بيانات PostgreSQL في إعداد العميل أبدا. عنوان
`https://activation.example.com` قيمة نموذجية وليست خدمة فعلية؛ يجب
استبداله بعنوان Cloud API المنشور قبل البناء.

## الواجهة والتجهيز التلقائي

تعرض النافذة للمستخدم فقط:

- اختيار البرنامج: `Restaurant` أو `Lab` أو `Jewelry`.
- حقل إدخال المعرف بصيغة `XXXX-XXXX-XXXX`.
- حقل رمز التفعيل الناتج.
- زر إنشاء رمز التفعيل وسطر حالة مختصر.

عند تشغيل `ActivateurRMS.exe` تفحص الواجهة backend المحلي تلقائيا. إذا لم
تجد خدمة `KeyGenService` جاهزة، تطلب صلاحية Administrator من Windows ثم:

1. التحقق من اتصال API والتوكن.
2. نسخ الخدمة وNSSM إلى `%ProgramFiles%\KeyGenRMS`.
3. إنشاء إعداد داخلي مصفى للخدمة المثبتة دون بيانات PostgreSQL.
4. تثبيت الخدمة وتشغيلها تلقائيا.

## توليد مفتاح

بعد ظهور رسالة الجاهزية:

1. اختر البرنامج الفعلي من القائمة.
2. أدخل كود طلب بصيغة `XXXX-XXXX-XXXX`.
3. اضغط `Generer la cle`.

تولد الخدمة المحلية المفتاح، تحفظه في قائمة انتظار محلية، ثم ترفعه إلى API
السحابي عند توفر الاتصال والسماح بالتوليد.

## حالة الصيانة

تتحقق الخدمة دوريا من حالة الخادم:

| القيمة | النتيجة |
| --- | --- |
| `1` | يسمح بتوليد المفاتيح ورفع السجلات |
| `0` | يوقف التوليد مؤقتا ويحافظ على البيانات المحلية |

إذا ظهرت رسالة صيانة في الواجهة، يجب على المسؤول إعادة الحالة إلى `1` من
لوحة التحكم أو API.

## إعدادات البناء الاختيارية

| المتغير | الاستخدام | الافتراضي |
| --- | --- | --- |
| `KEYGEN_LISTEN_ADDRESS` | عنوان الخدمة المحلية الذي تستعمله الواجهة أيضا | `127.0.0.1:45632` |
| `KEYGEN_DATA_DIR` | مجلد قائمة الانتظار والسجلات المساعدة | `C:\ProgramData\SystemLogs` |
| `KEYGEN_PRIMARY_LOG` | ملف سجل المفاتيح الأساسي | `C:\key_storage\generated_keys.txt` |
| `KEYGEN_STATUS_INTERVAL_SECONDS` | فترة فحص حالة الصيانة | `300` |
| `KEYGEN_UPLOAD_INTERVAL_SECONDS` | فترة محاولة رفع السجلات | `5` |

بعد تغيير `packaging\windows\.env` أعد بناء الحزمة. للاختبار الإداري فقط
يمكن وضع ملف `.env` بجانب التنفيذي لتجاوز القيم المضمّنة، ولا ينبغي توزيعه
على المستخدم النهائي.

## حل المشكلات السريع

| المشكلة | الحل |
| --- | --- |
| فشل التجهيز الأول | تأكد من HTTPS والتوكن والموافقة على طلب صلاحية Windows |
| فشل التوليد | تأكد من تشغيل خدمة `KeyGenService` وتطابق المنفذ في إعداد البناء |
| لا تظهر السجلات في الخادم | تحقق من اتصال API والتوكن؛ تبقى السجلات في قائمة الانتظار |
| التوليد موقوف | تحقق من حالة الصيانة في لوحة التحكم |
