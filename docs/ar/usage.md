# دليل استخدام Activateur RMS

هذا الدليل مخصص للشخص الذي يشغل مولد المفاتيح على Windows. لمعلومات البناء
وإعداد قاعدة البيانات راجع [دليل البناء والنشر](deployment.md).

## وظيفة البرنامج

تحتوي واجهة `ActivateurRMS.exe` على:

- اختيار المنتج من القائمة المعرفة في ملف `.env` المحلي.
- إدخال كود الطلب بصيغة `XXXX-XXXX-XXXX`.
- زر لتوليد مفتاح التفعيل وعرضه.

الواجهة لا تولد المفتاح بنفسها، بل ترسل الطلب إلى خدمة Rust محلية مثبتة
باسم `KeyGenService`. الخدمة هي التي تولد وتحفظ وترفع السجل لاحقا.

## محتويات حزمة التشغيل

```text
ActivateurRMS\
|-- ActivateurRMS.exe
|-- .env                         # يوضع محليا على جهاز التشغيل، وليس للتوزيع
|-- SHA256SUMS.txt
|-- KeyGenService\KeyGenService.exe
`-- nssm\nssm.exe
```

يجب إبقاء `KeyGenService\` و`nssm\` بجانب الواجهة، خصوصا عند تنفيذ أوامر
التثبيت أو التحديث أو الإزالة.

## التثبيت الأول

### قبل البدء

تأكد من الآتي:

1. يعمل الجهاز على Windows ويمكنه الاتصال بقاعدة PostgreSQL البعيدة.
2. يوجد ملف `.env` مهيأ بجانب `ActivateurRMS.exe` ويحتوي بيانات PostgreSQL
   وقائمة tokens وأسرارها.
3. الحالة في لوحة الإدارة هي `1`.
4. لديك إمكانية الموافقة على نافذة Administrator/UAC.

### بالتشغيل الرسومي

1. شغل `ActivateurRMS.exe`.
2. تفحص الواجهة خدمة Windows `KeyGenService` والـ backend المحلي.
3. إذا لم توجد الخدمة أو كانت قديمة أو مكسورة، تفحص PostgreSQL أولا.
4. إن كانت الحالة `1` تطلب الواجهة صلاحية Administrator وتثبت الخدمة.
5. تبدأ خدمة Rust وتكتب `AUTHORIZED.txt` بعد تفويضها الأول.
6. عندما يجيب backend المحلي، تظهر رسالة الجاهزية ويمكن التوليد.

### من CMD أو PowerShell

يمكن إجبار التثبيت أو التحديث أو الإصلاح:

```powershell
cd .\dist\windows\ActivateurRMS
.\ActivateurRMS.exe --install
```

هذا الأمر مفيد بعد استبدال الحزمة بإصدار أحدث أو عند ظهور خدمة مسجلة لكن
ملفاتها مفقودة. يتطلب اتصالا بـ PostgreSQL وحالة `1`، ويطلب UAC عند الحاجة.

## الاستخدام اليومي

1. افتح `ActivateurRMS.exe`.
2. انتظر رسالة الجاهزية.
3. اختر نوع البرنامج.
4. اكتب كود الطلب، مثلا `F81A-67A7-C6AA`.
5. اضغط زر التوليد.
6. سلم المفتاح الظاهر للغرض المخصص له.

عند نجاح التوليد تحفظ الخدمة العملية محليا فوريا. لا يعني ظهور المفتاح أن
السجل وصل إلى PostgreSQL في نفس اللحظة؛ إذا كانت الشبكة غير متاحة يوضع في
الطابور ويرفع تلقائيا لاحقا.

## تشغيل البرنامج دون إنترنت

| الحالة | هل يعمل التوليد دون إنترنت؟ |
| --- | --- |
| قبل أول تفويض ناجح | لا، لأن الخدمة الجديدة تحتاج قراءة `status=1` أولا |
| بعد إنشاء `AUTHORIZED.txt` وآخر حالة معروفة `1` | نعم، مع تخزين السجلات في الطابور |
| بعد استلام الحالة `0` | لا، حتى لو انقطع الإنترنت لاحقا |

## إدارة خدمة backend

نفذ الأوامر من مجلد الحزمة:

```powershell
.\ActivateurRMS.exe --install
.\ActivateurRMS.exe --uninstall
.\ActivateurRMS.exe --help
```

| الخيار | الاستخدام |
| --- | --- |
| `--install` | تثبيت أو تحديث أو إصلاح خدمة `KeyGenService` |
| `--uninstall` | إزالة الخدمة وملفات التثبيت |
| `--unstall` | اسم بديل مدعوم للإزالة |
| `--help` | عرض الخيارات |

عملية الإزالة:

- توقف وتحذف خدمة Windows.
- تحذف `%ProgramFiles%\KeyGenRMS`.
- لا تحذف `%ProgramData%\KeyGenRMS`، كي لا تضيع السجلات أو الطوابير.

إذا أردت حذف بيانات تاريخية محلية، افحصها وانسخها احتياطيا ثم احذفها
يدويا بقرار إداري منفصل.

## المسارات المحلية

### ملفات التثبيت

```text
%ProgramFiles%\KeyGenRMS\
|-- KeyGenService.exe
|-- nssm.exe
`-- .env
```

### ملفات البيانات

```text
%ProgramData%\KeyGenRMS\
|-- generated_keys.txt
|-- netcache.dat
|-- pending_uploads.json
|-- uploaded.log
|-- AUTHORIZED.txt
`-- MAINTENANCE.txt
```

| الملف | الغرض |
| --- | --- |
| `generated_keys.txt` | سجل نصي للمفاتيح المنشأة على الجهاز |
| `netcache.dat` | سجل محلي إضافي للمفاتيح المنشأة |
| `pending_uploads.json` | عناصر لم تؤكد الخدمة رفعها إلى PostgreSQL |
| `uploaded.log` | أثر محلي للعناصر التي أكدت الخدمة رفعها |
| `AUTHORIZED.txt` | يدل على أن الجهاز اجتاز تفويض التشغيل الأول |
| `MAINTENANCE.txt` | يدل على أن الجهاز استلم حالة الإيقاف `0` |

## التحديث إلى نسخة جديدة

1. ضع الحزمة الجديدة مع ملف `.env` المحلي الصحيح.
2. نفذ:

```powershell
.\ActivateurRMS.exe --install
```

3. وافق على UAC.
4. افتح الواجهة وتأكد من الجاهزية.
5. افحص لوحة الإدارة للتأكد من استمرار وصول السجلات.

تشغيل واجهة جديدة لا يكفي دائما لتحديث ملف الخدمة المثبت؛ أمر `--install`
هو الطريقة الصريحة لاعتماد backend الجديد.

ينطبق الأمر نفسه عند إضافة token جديد أو تغيير اسمه أو سرّه في `.env`:
نفذ `--install` كي تحمل خدمة Windows القائمة والسر الجديدين. عند تشغيل
الواجهة الجديدة مع خدمة تحمل قائمة قديمة، تكتشف الواجهة الاختلاف وتدخل
مسار التحديث المرخص.

## أين تراجع عند وجود مشكلة؟

راجع [دليل استكشاف الأخطاء](troubleshooting.md)، خاصة لحالات:

- `Demarrage du service impossible`.
- رفض التثبيت بسبب الحالة `0`.
- بقاء عناصر في `pending_uploads.json`.
- عدم ظهور سجلات في لوحة FastAPI.
