# المعمارية وتدفق البيانات

## الهدف

الغرض من النظام هو إعطاء واجهة بسيطة لتوليد مفاتيح منتجات قابلة للإضافة
من ملف `.env`، مع:

- استمرار التوليد دون إنترنت بعد اعتماد الجهاز أول مرة.
- تسجيل كل مفتاح محليا ثم رفعه إلى قاعدة PostgreSQL.
- تمكين المدير من إيقاف المولد عبر قيمة `0` وإعادته عبر قيمة `1`.
- عدم الحاجة إلى نشر API عامة على الإنترنت.

## المكونات وحدود المسؤولية

| المكون | مكان التشغيل | المسؤوليات | لا يقوم بـ |
| --- | --- | --- | --- |
| `ActivateurRMS.exe` | جهاز المولد | الواجهة، تثبيت/حذف/إصلاح الخدمة، إرسال طلب التوليد محليا | توليد المفتاح أو الكتابة إلى PostgreSQL |
| `KeyGenService.exe` | جهاز المولد كخدمة Windows | التوليد، التخزين المحلي، الطابور، قراءة الحالة ورفع السجلات | تقديم موقع إدارة أو تغيير الحالة |
| `nssm.exe` | جهاز المولد | إبقاء خدمة Rust عاملة تلقائيا | منطق أعمال البرنامج |
| PostgreSQL | الخادم البعيد | حفظ الحالة والسجلات | توليد المفاتيح أو تشغيل واجهة |
| FastAPI | جهاز الإدارة فقط | عرض سجلات PostgreSQL وتغيير الحالة | خدمة الواجهة الموزعة أو توليد المفاتيح |

## تدفق الاتصال

```text
                           اتصال SSL بـ PostgreSQL
                     +--------------------------------+
                     |                                |
                     v                                |
+--------------------------+          +-------------------------------+
| PostgreSQL البعيد        |<---------| FastAPI المحلي على جهاز المدير |
| server_control           |          | 127.0.0.1:8080                |
| activation_logs          |          +-------------------------------+
+--------------------------+
             ^
             | اتصال SSL مباشر لقراءة الحالة ورفع السجلات
             |
+--------------------------+        HTTP loopback فقط       +--------------------+
| KeyGenService.exe / NSSM |<-------------------------------| ActivateurRMS.exe   |
| 127.0.0.1:45632         |                                | واجهة Rust          |
+--------------------------+                                +--------------------+
```

لا تتصل الواجهة بالموقع المحلي ولا بقاعدة PostgreSQL أثناء التوليد. عند
التثبيت فقط تقرأ ملف `.env` المحلي لتفويض النسخة المرفقة ونسخ إعدادها إلى
الخدمة المثبتة.

## دورة تثبيت جهاز جديد

1. يوجد ملف `.env` بجانب الحزمة على جهاز المولد.
2. تفتح الواجهة أو ينفذ المدير `ActivateurRMS.exe --install`.
3. تشغل الواجهة backend المرفق مؤقتا بالأمر `--authorize-install`.
4. يتصل هذا الفحص بـ PostgreSQL ويقبل التثبيت فقط عندما تكون الحالة `1`.
5. بعد النجاح، تطلب الواجهة صلاحية Administrator.
6. تنسخ الملفات إلى `%ProgramFiles%\KeyGenRMS` وتسجل خدمة
   `KeyGenService` بواسطة NSSM مع التشغيل التلقائي.
7. تبدأ الخدمة. إذا لم يوجد `AUTHORIZED.txt` فإنها تقرأ `status=1` مرة
   أخرى، ثم تنشئ العلامة المحلية.
8. لا تعتبر الواجهة جاهزة إلا بعد نجاح `GET /health` من backend المثبت
   ومطابقة أسماء tokens فيه للقائمة المحلية؛ اختلاف القائمة يؤدي إلى تحديث الخدمة.

إذا كانت خدمة قديمة أو تشير إلى ملف مفقود، يعاملها التثبيت كحالة إصلاح:
يزيل التسجيل القديم ويستبدله بالخدمة الموجودة في الحزمة.

## دورة توليد مفتاح

```text
المستخدم يحدد المنتج والمعرف
          |
          v
ActivateurRMS.exe -> POST /generate_key -> KeyGenService.exe
                                            |
                                            | SHA-256 محلي بسر token من .env
                                            v
                              المفتاح + سجل محلي + pending_uploads.json
                                            |
                                      عند توفر الاتصال
                                            v
                                    INSERT activation_logs
```

المعرف يجب أن يكون بصيغة `XXXX-XXXX-XXXX`. النوع هو أحد الأسماء المرتبة في
`KEYGEN_TOKEN_IDS` داخل `.env`، ولا توجد أسماء أو أسرار منتجات ثابتة في
الكود التنفيذي.

## دورة المزامنة

- كل عملية توليد تكتب أولا على الجهاز، ولا تنتظر الشبكة.
- يوضع سجل JSON في `pending_uploads.json` مع `sync_id` فريد.
- تحاول الخدمة الرفع إلى PostgreSQL دوريا، افتراضيا كل 5 ثوان.
- يستعمل الإدخال `ON CONFLICT DO NOTHING` حتى لا تتكرر السجلات إذا أعيدت
  المحاولة بعد نجاح غير مؤكد.
- بعد نجاح المعاملة، تزال العناصر المرفوعة من الطابور وتكتب في `uploaded.log`.

## دورة الحالة `0/1`

تحاول الخدمة قراءة الحالة من PostgreSQL دوريا، افتراضيا كل 15 ثانية:

| القيمة المستلمة | ما يحدث محليا |
| --- | --- |
| `1` | يسمح بالتوليد ويحذف `MAINTENANCE.txt` إن وجد |
| `0` | يكتب `MAINTENANCE.txt` ويرفض أي مفتاح جديد |

إذا انقطع الإنترنت، لا توجد وسيلة فورية لوصول قيمة جديدة إلى الجهاز. لذلك:

- جهاز استلم `0` يبقى موقوفا حتى دون إنترنت.
- جهاز كانت آخر حالته `1` ثم انقطع يستمر بالتوليد ويحفظ الطابور حتى يعود
  الاتصال.

## الخدمتان المحليتان ليستا الشيء نفسه

| الخدمة | من يستخدمها | المنفذ الافتراضي | هل يجب أن تعمل دائما؟ |
| --- | --- | --- | --- |
| backend Rust | واجهة المولد | `127.0.0.1:45632` | نعم على جهاز المولد عبر NSSM |
| FastAPI الإداري | المدير عبر المتصفح | `127.0.0.1:8080` | فقط عند الحاجة للإدارة |
