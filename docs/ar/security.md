# الأمان وإدارة الأسرار

## حدود الثقة

- بيانات PostgreSQL تخص خادم API فقط.
- العميل يحتاج عنوان API وتوكن API لأنه يرفع سجلات التفعيل ويتلقى حالة
  الصيانة.
- يقرأ البناء `packaging/windows/.env` ويضمّن إعدادات العميل المصفاة في
  ملفات `exe`؛ لا يجب تتبع هذا الملف في Git أو توزيعه.

## قواعد التشغيل

1. لا تنسخ `services/cloud-api/.env` إلى حزمة العميل.
2. أنشئ `packaging/windows/.env` من `client.env.example` قبل البناء فقط.
3. استخدم HTTPS دائما بين العميل وCloud API؛ ينتقل التوكن والسجلات عبر هذا
   الاتصال.
4. دوّر `KEYGEN_API_SECRET_TOKEN` إذا خرج جهاز عميل من نطاق الثقة.
5. قيد وصول PostgreSQL إلى مضيف API قدر الإمكان.
6. اترك `FLASK_DEBUG=0` في الإنتاج.

## ملفات التوزيع

لا تتبع الملفات التنفيذية المبنية في Git. ينشئ `package.cmd` ملف
`SHA256SUMS.txt` مع الحزمة لمراجعة سلامة الملفات قبل التوزيع.

## ملاحظة عن التوكن

التوكن المضمّن في برنامج العميل قابل للاستخراج من ملف `exe`، لذلك لا
تعامله كسر إداري. التوكن الحالي مشترك بين العميل ولوحة التحكم وAPI. إذا
احتاج النظام إلى التوزيع خارج بيئة موثوقة، يجب فصل توكن رفع السجلات عن
توكن الإدارة وتقييد صلاحيات كل منهما.
