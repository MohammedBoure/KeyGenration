# الأمان وإدارة الأسرار

## حدود الثقة

- بيانات PostgreSQL تخص خادم API فقط.
- العميل يحتاج عنوان API وتوكن عميل محدود لأنه يطلب المفتاح ويتلقى حالة
  الصيانة، لكنه لا يستطيع تغييرها.
- يقرأ البناء `packaging/windows/.env` ويضمّن إعدادات العميل المصفاة في
  ملفات `exe`؛ لا يجب تتبع هذا الملف في Git أو توزيعه.

## قواعد التشغيل

1. لا تنسخ `services/cloud-api/.env` إلى حزمة العميل.
2. أنشئ `packaging/windows/.env` من `client.env.example` قبل البناء فقط.
3. استخدم HTTPS دائما بين العميل وCloud API؛ ينتقل توكن العميل والمفاتيح عبر هذا
   الاتصال.
4. استخدم `KEYGEN_ADMIN_SECRET_TOKEN` مستقلا في الخادم ولوحة الإدارة فقط،
   ولا تضعه في `packaging/windows/.env`.
5. دوّر `KEYGEN_API_SECRET_TOKEN` إذا خرج جهاز عميل من نطاق الثقة.
6. قيد وصول PostgreSQL إلى مضيف API قدر الإمكان.
7. اترك `FLASK_DEBUG=0` في الإنتاج.

## ملفات التوزيع

لا تتبع الملفات التنفيذية المبنية في Git. ينشئ `package.cmd` ملف
`SHA256SUMS.txt` مع الحزمة لمراجعة سلامة الملفات قبل التوزيع.

## ملاحظة عن التوكن

توكن العميل المضمّن في برنامج العميل قابل للاستخراج من ملف `exe`، لذلك لا
يعطيه الخادم صلاحية `set-status` أو قراءة سجلات الإدارة. توكن الإدارة
المنفصل هو الوحيد الذي يغير الحالة.

## حدود الحماية

لا يمكن منع نسخ ملف `exe` المرسل إلى جهاز البائع أو منع محاولة تعديله
بضمان مطلق. الحماية القابلة للتنفيذ هي ألا يحتوي ذلك الملف خوارزمية
التوليد أو توكن الإدارة: النسخة الجديدة تطلب المفتاح من الخادم، والخادم
يرفض الطلب عندما تكون الحالة `0`.

أي نسخة قديمة سبق توزيعها وكانت تولد المفاتيح محليا يجب سحبها واستبدالها؛
لا يمكن حذف خوارزمية أصبحت موجودة بالفعل على جهاز خارجي عن بعد.
